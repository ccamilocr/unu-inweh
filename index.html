Version Control & Deployment Workflows

Git-based development with structured branching, staged deployments, and automated backup protocols for production UN environments.

Git / GitHub — Workflow & Deployment Practices

Applied across FAO, UNDP, IDPC · Private repos per institutional data governance policy

All development follows a structured Git workflow with feature branching, staged environments, and versioned releases. Institutional repositories are private per UN data governance requirements; a public example is available via the burn scar algorithm.

Branching

Feature branches per unit, pull requests before merging to main. Hotfix branches for production patches.

Pipeline

Feature → review → staging → Docker rebuild → tagged release. Rollback via Docker image versioning.

Backup

Automated pg_dump cron jobs, Docker volume snapshots, environment configs in private repo with secrets management.

Security

No hardcoded credentials. Production deployments require tagged releases. Access via SSH keys and GitHub permissions.

Release Workflow
# Feature development
git checkout -b feature/ai-ats-cv-pipeline
git commit -m "Add AI scoring for CV shortlisting"

# After review — release
git checkout main && git merge feature/ai-ats-cv-pipeline
git tag -a v2.1.0 -m "CV AI scoring pipeline"
docker-compose pull && docker-compose up -d --build
